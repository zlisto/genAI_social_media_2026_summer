What makes a game fun?

DESIGN CHECKLIST

  • Clear goal — player knows what to try next
  • Readable verbs — controls feel obvious fast
  • Fair challenge — hard enough to care, not random
  • Fast feedback — every action gets a reaction
  • Mastery loop — slightly better each attempt
  • Fantasy fit — verbs match the character

Use this before you ask an agent for art

Fun = interesting decisions + satisfying feedback.

  • Pretty art cannot rescue a boring loop
  • A sharp loop can survive rough art
  • Prototype the feeling, then decorate it

Stage 1 · Tips

Choosing a good concept

DO

  • One hero + one prop
  • One verb beyond walking
  • One collectible or enemy type
  • Three micro-levels or rooms
  • Re-skin a Zelda/Mario structure — keep the loop, change the look/characters

Same bones, new skin (rabbit market ≠ invent a new genre)

DON’T

  • MMO / crafting / skill trees
  • Realistic humans on day one
  • Everything including multiplayer
  • Story longer than the playable loop
  • Commission art before rules exist

Scope kills more games than taste

Best pitch: noun + place + goal.

“Boxing rabbit · night market · collect 10 carrots before dawn.”

Stage 2 · SFX cues

Sound starts in Mechanics — as a shopping list

SFX = sound effects (short blips). Mechanics does not make WAV files — it names when and how they should feel.

REQUIRED CUE IDS (CLASS STANDARD)

  • jump · punch · hurt
  • stomp (enemy defeated)
  • pickup_heal · pickup_power
  • win · lose

Stable ids the Sound Agent must hit

EACH SFX Cue = 3 FIELDS

  • id — filename later: sfx_jump.wav
  • trigger — when it fires (“player leaves ground”)
  • mood — design note (“soft cotton hop”)

Mood text steers the blip synthesizer

// mechanics.json → sfx[]
{ "id": "punch", "trigger": "player attacks", "mood": "glove thwack", "category": "combat" }
{ "id": "pickup_heal", "trigger": "collect carrot", "mood": "bright healthy chime", "category": "pickup" }

Same pattern as art: spec first, pixels (and samples) later.

Stage 3 · Background music

Levels also design the soundtrack mood

BGM = background music — a looping layer for the whole level. Different from SFX (one-shots on actions).

PER LEVEL TRACK

  • id — e.g. meadow_punch
  • level_id — must match the map
  • mood — “sunny meadow stroll”
  • tempo_bpm — e.g. 118
  • levels[].music_id points at that track

Teach → twist in the music, too

WHY LEVELS, NOT MECHANICS?

  • SFX = action verbs (mechanics owns the verbs)
  • BGM = place / pace (levels own the journey)
  • Level 2 can be darker, faster, braver
  • Sound Agent turns each brief into a short chiptune loop

Two shopping lists: ears for events + ears for space

SFXjump · punch · coin
BGMlevel loop
Bothtext briefs first

You do not need a composer for class games — you need clear mood strings the Sound Agent can follow.

Stage 3 · Physics handoff

Levels must obey mechanics (jump height)

THE TRAP

  • Levels Agent draws platforms that look cool
  • It does not automatically know jump physics
  • Result: floating ledges the player can never reach
  • Pretty ASCII ≠ playable geometry

Vibes placed the tiles — gravity didn’t approve

THE FIX · HARNESS

  • From mechanics.json: jump speed + gravity → max_jump_tiles
  • Tell Levels Agent: platforms ≤ that many tiles above the floor
  • Stair-step climbs (1–2 tiles), not sky islands
  • Post-check: lower / remove illegal = platforms

Mechanics numbers gate the map

Mechanicsjump + gravity
Derivemax_jump_tiles
Levelsplace within reach

Side-scrollers: if a ledge needs a 4-tile jump and Mario only has 2, the map is wrong — not the player.

Stage 3 · Level design tips

What to tell the Levels Agent (you don’t hand-draw maps)

SIZE · KEEP IT TINY

  • Zelda-like: 3–5 rooms per dungeon, ~10–16 tiles wide
  • Pattern: teach room → locked door → key → boss
  • Overworld: 1 small hub + 1–2 exits (house / cave)
  • Mario-like: 1 short run, ~30–50 tiles wide
  • Teach jump → one enemy → one gap → exit flag

Finishable maps beat “epic” empty maps

ASK THE AGENT TO SHOW THE LAYOUT

  • Yes — it can preview the map before final art
  • Put an ASCII / tile-ID grid in levels.json
  • Also export layout_preview.html or a PNG
  • Colored blocks = floor / wall / spawn / exit
  • You approve the shape, then Art Agent skins tiles

Layout sketch ≠ pretty art — it’s a blueprint

WHY NOT “MAKE A SONG WITH AI” FIRST?

  • GenAI music is slow, pricey, hard to critique
  • Class games need readable feedback more than a OST
  • Blips library (jsfxr-style) synthesizes short WAV from params
  • Cute cartoon hops / punches / coins in milliseconds

Procedural SFX ≈ HTML pipeline for ears

WHAT THE SOUND AGENT OUTPUTS

  • data/sound.json — BlipRecipe + MusicRecipe
  • assets/sfx_jump.wav, sfx_punch.wav, …
  • assets/bgm_meadow_punch.wav (loop)
  • Ids must match mechanics / levels

Recipes first — then the synth writes WAV

Tell agents: event → sound id. Don’t hand-pick thousands of free samples unless you want to.

Stage 5 · Sound Agent · Recipes

jsfxr-style params (the blip formula)

jsfxr (from classic sfxr): knobs for wave / pitch / length → short .wav blips — not a recording studio. The agent fills knobs; code synthesizes the sample.

WHAT IT IS (IN ONE BREATH)

  • Procedural SFX: math → beep, not “generate a song with AI”
  • Built for jump / coin / hit / laser / explode vibes
  • Output is a few hundred milliseconds of audio
  • Cheap, remix-safe, easy for an agent to specify as text/numbers

Like an art shopping list — but for ears

WHY WE USE “JSFXR-STYLE”

  • The agent writes params (wave, freq, decay…)
  • Code synthesizes sfx_jump.wav, etc.
  • No stock library download; no big generative-audio bill
  • Mood text (“soft cotton hop”) nudges the knobs

Readable cartoon blips for student games

SFX · BlipRecipe

  • wave square / saw / sine / noise
  • start_freq_hz → end_freq_hz
  • duration_ms (~80–350) · attack / decay

BGM · MusicRecipe (SAME IDEA, LONGER)

  • Short chiptune loop from scale + tempo
  • Levels write the mood; Sound builds the loop
jumppitch up blip
punchnoise thwack
healbright chime
losesad fall

jsfxr = knobs → blip. Agents fill the knobs; Phaser just plays the WAV.

Stage 5 · Assembler + audio

Wire sound the same way you wire damage

Phaser only plays files you put in memory first. Then you call play on the same moments you update score / HP / juice.

PHASER · THREE JOBS (IN ORDER)

  • 1 · Preload — download every WAV once at boot
    e.g. key sfx_jump ← file assets/sfx_jump.wav
  • 2 · Create / level start — start the looping BGM for this map
    Look up level.music_id → play bgm_… with loop: true
  • 3 · Gameplay events — one short SFX when something happens
    Jump key → playSfx("jump") · punch → "punch" · same id as mechanics.sfx

JSON id = Phaser audio key = filename stem

WHEN TO CALL EACH SFX

  • jump — player leaves the ground
  • punch — attack button
  • hurt — player takes damage
  • stomp — enemy defeated
  • pickup_heal / pickup_power — items
  • win / lose — end of run

Same hooks as score / juice

BROWSER GOTCHA

  • No sound until first click / key (autoplay rules)
  • Use http:// server, not file://

MINI FLOW

Mechanics lists cue ids → Sound writes WAVs → Assembler preload + play on events

Think: preload = put records on the shelf · create = start the radio loop · events = hit play on each blip.

STILL NEED (TO PLAY)

  • Read keyboard / touch input
  • Move the camera, draw tiles + sprites

  • HUD + sound.play on the same events

That’s the Assembler’s job in a framework

Folders of PNGs (and WAVs) don’t play. Something has to run the loop and connect inputs → rules → pictures → sounds.
